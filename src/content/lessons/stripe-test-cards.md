আগের লেসনে আমরা PaymentIntent-এর স্ট্যাটাসগুলো চিনেছি। এবার সেগুলো নিজের চোখে ঘটাব। Stripe কিছু বিশেষ টেস্ট কার্ড নম্বর দেয়, যার প্রতিটি একটা নির্দিষ্ট দৃশ্য তৈরি করে: সফল, টাকা নেই, চুরি যাওয়া কার্ড, 3D Secure ইত্যাদি।

একজন ম্যানুয়াল টেস্টারের জন্য এগুলো সোনার খনি। আসল কার্ড বা আসল টাকা ছাড়াই প্রায় সব বাস্তব পরিস্থিতি পরীক্ষা করা যায়।

## এই লেসনে যা শিখবেন

- Stripe-এর মূল টেস্ট কার্ড আর প্রতিটির প্রত্যাশিত ফল
- মেয়াদ, CVC, পোস্টাল কোডের নিয়ম
- Decline code কী (`card_declined` + `decline_code`) এবং কীভাবে পড়বেন
- 3D Secure কীভাবে টেস্ট করবেন (মডালে পাস ও ফেইল)
- প্রতিটি দৃশ্যে UI, Dashboard ও ডেটাবেসে কী যাচাই করবেন

## টেস্ট কার্ডের নিয়ম

- এই কার্ড শুধু Test Mode বা Sandbox-এ কাজ করে। Live Mode-এ দিলে প্রত্যাখ্যাত হবে।
- **মেয়াদ:** যেকোনো ভবিষ্যতের তারিখ, যেমন `12/34`।
- **CVC:** যেকোনো ৩ সংখ্যা, যেমন `123` (American Express টেস্ট কার্ডে ৪ সংখ্যা)।
- **পোস্টাল কোড বা ZIP:** যেকোনো মান, যেমন `12345`। কোন দেশ বাছাই করেছেন তার উপর ফর্মে এই ঘর আসতে পারে বা না-ও আসতে পারে।
- নাম, ইমেইল: যেকোনো কাল্পনিক মান। আসল ব্যক্তিগত তথ্য দেবেন না।

> [!LIVE]
> Live Mode-এ কখনো আসল কার্ড দিয়ে “শুধু দেখার জন্য” টেস্ট করবেন না, আর অন্যের কার্ড তো কখনোই না। Stripe-এর শর্তও Live-এ টেস্টিংয়ের জন্য আসল কার্ড ব্যবহার নিষেধ করে। সব টেস্ট Test Mode বা Sandbox-এ।

> [!NOTE]
> Stripe সময়ে সময়ে টেস্ট কার্ড যোগ বা বদলায়। কাজ শুরুর আগে প্রতিবার অফিসিয়াল তালিকা মিলিয়ে নিন: https://docs.stripe.com/testing

## Decline code পড়া

কার্ড প্রত্যাখ্যাত হলে Stripe একটি এরর অবজেক্ট দেয়। দুই স্তরের তথ্য থাকে:

- `code`: সাধারণ ধরন, যেমন `card_declined`, `expired_card`, `incorrect_cvc`, `processing_error`।
- `decline_code`: `card_declined` হলে ব্যাংকের দেওয়া আরও নির্দিষ্ট কারণ, যেমন `insufficient_funds`, `lost_card`।

```json
{
  "error": {
    "type": "card_error",
    "code": "card_declined",
    "decline_code": "insufficient_funds",
    "message": "Your card has insufficient funds.",
    "payment_intent": {
      "id": "pi_XXXXXXXX",
      "status": "requires_payment_method"
    },
    "request_log_url": "https://dashboard.stripe.com/test/logs/req_XXXXXXXX"
  }
}
```

এই উত্তর আপনি দেখতে পাবেন DevTools-এর Network ট্যাবে (Stripe.js-এর রিকোয়েস্টে) বা Dashboard → Developers → Logs-এ। Dashboard-এর পেমেন্ট পেজেও প্রত্যাখ্যানের কারণ লেখা থাকে।

> [!TIP]
> কাস্টমারকে কী বলবেন আর লগে কী রাখবেন, দুটো আলাদা। লগে পুরো `decline_code` রাখুন, যাতে সাপোর্ট টিম বুঝতে পারে। কিন্তু `lost_card`, `stolen_card` বা Radar ব্লকের মতো ক্ষেত্রে কাস্টমারকে সাধারণ বার্তা দেখানো উচিত, যেমন “কার্ডটি গ্রহণ করা যায়নি, অন্য কার্ড চেষ্টা করুন”। এতে প্রতারকরা চুরি করা কার্ড যাচাই করার সুযোগ কম পায়।

## 3D Secure কীভাবে টেস্ট করবেন

3D Secure (3DS, কার্ডধারীর বাড়তি যাচাই, যেমন ব্যাংকের OTP) ইউরোপসহ অনেক দেশে বাধ্যতামূলক, আর বাংলাদেশের কার্ডেও OTP যাচাই পরিচিত। Stripe Test Mode-এ আসল OTP আসে না। তার বদলে একটি টেস্ট মডাল খোলে।

1. 4000 0025 0000 3155 বা 4000 0000 0000 3220 দিয়ে পেমেন্ট দিন।
2. একটি পপআপ বা মডাল খুলবে, যেখানে সাধারণত **Complete** আর **Fail** জাতীয় দুটি বাটন থাকে।
3. **Complete** চাপলে যাচাই সফল, পেমেন্ট `succeeded` হওয়ার কথা।
4. আবার নতুন পেমেন্টে **Fail** চাপলে যাচাই ব্যর্থ, PaymentIntent ফিরে যায় `requires_payment_method`-এ।
5. তৃতীয়বার মডাল খুলে কিছু না চেপে বন্ধ করে দিন বা ট্যাব রিফ্রেশ করুন। অ্যাপ কী করে দেখুন।

স্ক্রিনশট বর্ণনা: চেকআউট পেজের উপরে একটি ধূসর পর্দা, মাঝে সাদা বাক্স, যেখানে লেখা থাকে এটি একটি টেস্ট 3D Secure পেজ, আর নিচে Complete ও Fail বাটন।

3DS-এ টেস্টারের নজর:

- মডাল মোবাইলের ছোট পর্দায় ঠিকমতো দেখায় ও বন্ধ করা যায় কি না।
- Fail-এর পর পরিষ্কার মেসেজ আর আবার চেষ্টার সুযোগ আছে কি না।
- মডাল বন্ধ করলে বা রিফ্রেশ করলে অর্ডার ভুল করে Paid হয় না।
- Complete-এর পর একবারই চার্জ হয়, দুইবার নয়।

## হাতেকলমে অনুশীলন

কোনো অ্যাপ না থাকলেও Stripe-এর নিজের টুল দিয়ে অনুশীলন করা যায়। Dashboard-এ **Payment Links** দিয়ে কয়েক ক্লিকে একটি টেস্ট পেমেন্ট পেজ বানানো যায়।

1. Test Mode বা Sandbox-এ আছেন কি না নিশ্চিত করুন।
2. Dashboard-এ একটি পণ্য বানান: “Payment QA Course”, দাম ধরুন 20 USD।
3. সেই পণ্যের জন্য একটি **Payment Link** তৈরি করুন এবং লিংকটি নতুন ট্যাবে খুলুন।
4. একটি স্প্রেডশিট বানান, কলাম: কার্ড, দৃশ্য, প্রত্যাশিত, প্রাপ্ত, UI মেসেজ, Dashboard স্ট্যাটাস, পাস বা ফেইল।
5. উপরের টেবিলের প্রতিটি কার্ড দিয়ে একবার করে পেমেন্ট চেষ্টা করুন। মেয়াদ `12/34`, CVC `123`।
6. প্রতিবার UI-তে কী দেখাল লিখুন, তারপর Dashboard → Payments-এ সেই চেষ্টা খুঁজে স্ট্যাটাস ও কারণ লিখুন।
7. 3155 কার্ডে একবার Complete, একবার Fail, একবার মডাল বন্ধ করে দেখুন।
8. Developers → Logs-এ একটি প্রত্যাখ্যাত রিকোয়েস্ট খুলে `decline_code` খুঁজুন।

- 0002, 9995, 9987, 9979: Payment Link পেজেই এরর মেসেজ আসবে, Dashboard-এ Failed এবং কারণ। লক্ষ্য করুন হারানো ও চুরির ক্ষেত্রে Stripe-এর পেজ সাধারণ ভাষায় প্রত্যাখ্যান দেখায়।

- 3155 ও 3220: টেস্ট মডাল; Complete-এ সফল, Fail-এ ব্যর্থ ও আবার চেষ্টা।

> [!MISTAKE]
> - শুধু 4242 দিয়ে টেস্ট করে “পেমেন্ট কাজ করে” রিপোর্ট দেওয়া।
> - প্রত্যাখ্যানের পর শুধু UI দেখা, ডেটাবেসে অর্ডার ভুল করে Paid হলো কি না না দেখা।
> - মেয়াদ হিসেবে অতীতের তারিখ দিয়ে ভুল দৃশ্য তৈরি করা, তারপর ভুল বাগ রিপোর্ট করা।
> - বাগ রিপোর্টে কার্ড নম্বর লিখে Request ID বা PaymentIntent আইডি না দেওয়া।
> - Live Mode-এ টেস্ট কার্ড দিয়ে “কাজ করছে না” বলে বাগ রিপোর্ট করা।

## সারসংক্ষেপ

- Stripe টেস্ট কার্ড শুধু Test Mode বা Sandbox-এ; মেয়াদ যেকোনো ভবিষ্যৎ, CVC যেকোনো ৩ সংখ্যা, পোস্টাল কোড যেকোনো।
- প্রতিটি কার্ড একটি নির্দিষ্ট দৃশ্য: সফল, প্রত্যাখ্যান, মেয়াদ, CVC, প্রসেসিং এরর, 3DS, হারানো, চুরি, Radar ব্লক।
- প্রত্যাখ্যানে `code` আর `decline_code` পড়ুন; কাস্টমারকে সংবেদনশীল কারণ দেখাবেন না।
- 3DS টেস্ট মডালে Complete, Fail আর বন্ধ করা তিনটিই পরীক্ষা করুন।
- প্রতিটি টেস্টে UI, Dashboard আর ডেটাবেস তিনটিই মিলিয়ে দেখুন; তালিকা নিয়মিত https://docs.stripe.com/testing থেকে যাচাই করুন।

## বাড়ির কাজ

1. উপরের অনুশীলনের স্প্রেডশিট সম্পূর্ণ করুন, ১১টি কার্ডই।
2. যেকোনো একটি দৃশ্যে যেখানে UI মেসেজ আপনার কাছে অস্পষ্ট মনে হয়েছে, তা নিয়ে একটি ছোট উন্নতির পরামর্শ লিখুন।
3. পরের সপ্তাহে এই দৃশ্যগুলো দিয়ে গোছানো [পেমেন্ট টেস্ট কেস](/lessons/payment-test-cases/) লিখব এবং [বাগ রিপোর্ট](/lessons/payment-bug-reports/) করা শিখব। কার্ডের দ্রুত তালিকা পাবেন [চিটশিটে](/cheatsheet/)।
