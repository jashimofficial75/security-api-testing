আগের দুই লেসনে আমরা শিখেছি পেমেন্ট কীভাবে চলে এবং API কোন ভাষায় কথা বলে। এবার নিজের একটা খেলার মাঠ বানাব: একটি ফ্রি Stripe অ্যাকাউন্ট, যেখানে আসল টাকা ছাড়াই পেমেন্ট, রিফান্ড, Webhook সব টেস্ট করা যায়।

এই কোর্সের প্রায় সব হাতেকলমে কাজ এই অ্যাকাউন্টেই হবে। তাই ধীরে, সাবধানে সেটআপ করুন।

## এই লেসনে যা শিখবেন

- ফ্রিতে Stripe অ্যাকাউন্ট খোলা, ধাপে ধাপে
- Dashboard ঘুরে দেখা: Payments, Customers, Developers, API keys, Webhooks, Logs, Events
- Test Mode, Sandbox আর Live Mode-এর পার্থক্য
- API Key-এর তিন ধরন: Publishable, Secret, Restricted
- Secret Key কেন কখনো শেয়ার করবেন না, আর ফাঁস হলে কী করবেন

## Stripe অ্যাকাউন্ট খোলা

Stripe-এ অ্যাকাউন্ট খোলা ফ্রি, কার্ড লাগে না।

1. ব্রাউজারে https://stripe.com খুলুন, **Sign in** বা **Start now** জাতীয় বাটনে যান।
2. ইমেইল, পুরো নাম, দেশ ও একটি শক্ত পাসওয়ার্ড দিন। দেশ হিসেবে তালিকায় যা পাওয়া যায় বাছুন।
3. ইমেইলে আসা ভেরিফিকেশন লিংকে ক্লিক করে ইমেইল নিশ্চিত করুন।
4. Dashboard খুললে ব্যবসার তথ্য চাইতে পারে। শেখার জন্য এগুলো এখনই পূরণ করা লাগে না, **Skip** বা পরে করার অপশন খুঁজুন।
5. নিশ্চিত হোন আপনি Test Mode বা একটি Sandbox-এ আছেন (নিচে বিস্তারিত)।
6. সাথে সাথে **Two-step authentication** (দুই ধাপের লগইন যাচাই) চালু করুন, অ্যাকাউন্ট সেটিংসে পাবেন।

> [!NOTE] বাংলাদেশ থেকে শেখার জন্য
> Test Mode-এ শেখার জন্য সাধারণত ব্যবসা যাচাই লাগে না; Live চালু করার শর্ত দেশভেদে আলাদা — Stripe-এর সাইটে দেখে নিন। এই কোর্সে আমাদের Live লাগবেই না, তাই বাংলাদেশি শিক্ষার্থীরাও পুরো কোর্স Test Mode-এ করতে পারবেন।

Stripe-এর ইন্টারফেস মাঝে মাঝে বদলায়। কোনো বাটন বা মেনুর নাম হুবহু না মিললে আশেপাশে একই অর্থের অপশন খুঁজুন, বা [Stripe Docs](https://docs.stripe.com)-এ সার্চ করুন।

## Test Mode, Sandbox আর Live Mode

### Test Mode বনাম Live Mode

| বিষয় | Test Mode | Live Mode |
|---|---|---|
| টাকা | কোনো আসল টাকা নড়ে না | আসল কাস্টমারের আসল টাকা |
| কার্ড | শুধু Stripe-এর টেস্ট কার্ড (যেমন 4242 4242 4242 4242) | শুধু আসল কার্ড |
| API Key | `pk_test_`, `sk_test_`, `rk_test_` | `pk_live_`, `sk_live_`, `rk_live_` |
| ব্যবসা যাচাই | শেখার জন্য সাধারণত লাগে না | লাগে, দেশভেদে শর্ত আলাদা |
| ডেটা | আলাদা, Live-এ দেখা যায় না | আলাদা, Test-এ দেখা যায় না |
| ফি | নেই | প্রতি লেনদেনে ফি |
| QA-এর কাজ | সব টেস্ট এখানে | সাধারণত শুধু অনুমতি নিয়ে ছোট স্মোক টেস্ট, নিয়ম মেনে |

### Sandbox কী

Stripe এখন Test Mode-এর পাশাপাশি **Sandboxes** নামে একটি ব্যবস্থা দেয়। মোটা দাগে, Sandbox হলো আলাদা আলাদা টেস্ট পরিবেশ। প্রতিটির নিজস্ব ডেটা, সেটিংস আর API Key থাকে। ফলে একটা Sandbox-এ পরীক্ষা করে নষ্ট করলেও অন্যটা পরিষ্কার থাকে, আর টিমের সদস্যদের আলাদা পরিবেশ দেওয়া যায়।

- Dashboard-এর উপরের দিকে অ্যাকাউন্ট বা পরিবেশ বাছাইয়ের মেনুতে সাধারণত Sandbox তৈরি ও বদলানোর অপশন থাকে।
- Sandbox-এর কী-ও দেখতে `sk_test_`, `pk_test_` দিয়ে শুরু হয়।
- কোনটি কখন পাওয়া যায় এবং কী কী সীমা আছে, তা Stripe সময়ের সাথে আপডেট করে। [Stripe Docs](https://docs.stripe.com)-এ “sandboxes” লিখে সার্চ করে বর্তমান নিয়ম দেখে নিন।

এই কোর্সে “Sandbox” বলতে আমরা Test Mode বা Stripe Sandbox, যেকোনো টেস্ট পরিবেশ বোঝাব। দুটোতেই কাজ চলবে।

> [!LIVE]
> Live Mode-এ কখনো টেস্ট করবেন না যদি না টিম লিখিতভাবে বলে। Live-এ প্রতিটি পেমেন্ট আসল টাকা, আসল ফি আর আসল কাস্টমার। স্ক্রিনে টগল বা পরিবেশের নাম সবসময় দেখে নিন। কাজ শুরুর আগে নিজেকে প্রশ্ন করুন: “আমি কি Test-এ আছি?”

## Dashboard ঘুরে দেখা

বাম পাশের মেনু আর উপরের সার্চ বার দিয়ে সব জায়গায় যাওয়া যায়। QA-এর জন্য জরুরি জায়গাগুলো:

| জায়গা | কী পাবেন | QA কীভাবে ব্যবহার করে |
|---|---|---|
| Payments (Transactions) | সব পেমেন্টের তালিকা, স্ট্যাটাস, অঙ্ক | টেস্ট পেমেন্ট সফল, ব্যর্থ বা রিফান্ড হলো কি না মেলানো |
| Customers | কাস্টমার, তাদের সেভ করা কার্ড ও পেমেন্ট | ঠিক কাস্টমারের সাথে পেমেন্ট যুক্ত হলো কি না |
| Developers → API keys | Publishable, Secret, Restricted কী | কী দেখা, Roll করা, Restricted কী তৈরি |
| Developers → Webhooks | Webhook endpoint আর ডেলিভারির ইতিহাস | ইভেন্ট গেল কি না, কোন Status Code ফেরত এলো |
| Developers → Logs | প্রতিটি API Request ও Response | এরর হলে কোন রিকোয়েস্ট, কোন প্যারামিটার, কী উত্তর |
| Developers → Events | পেমেন্টে যা ঘটেছে তার টাইমলাইন | যেমন `payment_intent.succeeded` কখন তৈরি হলো |

> [!TIP]
> নতুন Dashboard-এ Developers অংশ “Workbench” নামের একটি প্যানেলেও দেখাতে পারে। নাম যা-ই হোক, Logs আর Events খুঁজে বের করুন। একটা পেমেন্ট ফেইল হলে প্রথমে Logs-এ গিয়ে সেই Request-এর Response দেখুন। ডেভেলপারকে বাগ রিপোর্টে Request ID (`req_` দিয়ে শুরু) দিলে তিনি সাথে সাথে খুঁজে পাবেন।

একটি পেমেন্টের বিস্তারিত পেজে ক্লিক করলে দেখবেন অঙ্ক, স্ট্যাটাস, কার্ডের শেষ চার ডিজিট, টাইমলাইন, আর সংশ্লিষ্ট Events। এই পেজটাই আপনার প্রমাণের জায়গা।

## API Key: তিন ধরন

Developers → API keys-এ গেলে দেখবেন:

| কী | শুরু হয় | কোথায় থাকতে পারে | কী করা যায় |
|---|---|---|---|
| Publishable Key | `pk_test_` | ব্রাউজার, মোবাইল অ্যাপ, ফ্রন্টএন্ড কোড | সীমিত কাজ, যেমন Stripe.js দিয়ে কার্ড তথ্য নিরাপদে নেওয়া |
| Secret Key | `sk_test_` | শুধু সার্ভারে, এনভায়রনমেন্ট ভেরিয়েবল বা Secret Manager-এ | প্রায় সব কাজ: পেমেন্ট, রিফান্ড, কাস্টমার ডেটা |
| Restricted Key | `rk_test_` | সার্ভার বা নির্দিষ্ট থার্ড-পার্টি টুলে | শুধু যে অনুমতি দেবেন (যেমন পেমেন্ট শুধু পড়া) |

Postman-এ API টেস্ট করার সময় আমরা Secret Key ব্যবহার করব এভাবে, তবে কখনো আসল কী লিখে কোথাও শেয়ার করব না:

```bash
curl https://api.stripe.com/v1/customers \
  -u sk_test_XXXXXXXXXXXXXXXX:
```

শেষে `:` আছে কারণ Stripe কী-কে ইউজারনেম হিসেবে নেয়, পাসওয়ার্ড ফাঁকা। চাইলে `Authorization: Bearer sk_test_XXXXXXXXXXXXXXXX` হেডারও দিতে পারেন।

### কেন Secret Key কখনো শেয়ার নয়

Test Secret Key দিয়েও কেউ আপনার Sandbox-এর সব কাস্টমার, পেমেন্ট দেখতে, বদলাতে, মুছতে পারে। Live Secret Key হলে তো আসল টাকা আর আসল কাস্টমারের ডেটা ঝুঁকিতে।

কখনো যেখানে রাখবেন না:

- GitHub বা অন্য কোনো রিপোজিটরিতে কমিট (প্রাইভেট রিপোতেও না)। স্বয়ংক্রিয় বট মিনিটের মধ্যে পাবলিক রিপো স্ক্যান করে কী খুঁজে নেয়।
- ফ্রন্টএন্ড কোড, মোবাইল অ্যাপ, বা `PUBLIC_` বা `NEXT_PUBLIC_` জাতীয় পাবলিক ভেরিয়েবলে।
- স্ক্রিনশট, স্ক্রিন রেকর্ডিং, ইউটিউব টিউটোরিয়াল।
- বাগ রিপোর্ট, Jira, Slack, WhatsApp, ইমেইল।
- Postman-এর পাবলিক ওয়ার্কস্পেস বা শেয়ার করা কালেকশন।

নিরাপদ উপায়: কী থাকবে `.env` ফাইলে (যেটা `.gitignore`-এ আছে), বা CI-এর Secret-এ, বা Postman-এর লোকাল ভেরিয়েবলে।

```text
# .env  (এই ফাইল কখনো কমিট হবে না)
STRIPE_SECRET_KEY=sk_test_XXXXXXXXXXXXXXXX
STRIPE_PUBLISHABLE_KEY=pk_test_XXXXXXXX
```

### ফাঁস হলে কী করবেন: কী Roll করা

1. দেরি না করে Dashboard → Developers → API keys-এ যান।
2. ফাঁস হওয়া কী-এর পাশের মেনু থেকে **Roll key** বাছুন। Stripe নতুন কী দেবে, আর পুরোনোটা বাতিল করবে (সাথে সাথে বা আপনার বাছাই করা সময় পরে)। ফাঁস হলে সাথে সাথে বাতিল বাছাই করুন।
3. নতুন কী সার্ভার বা `.env`-এ বসান।
4. টিম লিড বা সিকিউরিটি টিমকে জানান। লুকাবেন না, দ্রুত জানানোই পেশাদারিত্ব।
5. Logs-এ দেখুন অপরিচিত কোনো রিকোয়েস্ট হয়েছে কি না।
6. যেখানে ফাঁস হয়েছে (পোস্ট, কমিট), সেখান থেকে মুছুন। Git ইতিহাসেও থেকে যায়, তাই Roll করাটাই আসল সমাধান।

> [!DANGER]
> কোনো টিউটোরিয়াল, ফোরাম বা “ফ্রি API কী” ওয়েবসাইট থেকে অন্য কারো কী কখনো ব্যবহার করবেন না। সবসময় নিজের অ্যাকাউন্টের নিজের কী।

## হাতেকলমে অনুশীলন

1. উপরের ধাপে Stripe অ্যাকাউন্ট খুলুন এবং Two-step authentication চালু করুন।
2. Test Mode বা একটি Sandbox-এ আছেন কি না নিশ্চিত করুন। স্ক্রিনের কোথায় তা লেখা আছে নোট করুন।
3. Developers → API keys-এ যান। Publishable Key আর Secret Key কোথায় দেখায় খুঁজুন। Secret Key দেখতে সাধারণত “Reveal” চাপতে হয়। শুধু শুরুর অংশ (`sk_test_`) নোট করুন, পুরো কী কোথাও লিখবেন না।
4. একটি Restricted Key তৈরি করুন: নাম দিন “qa-read-only”, শুধু Charges বা PaymentIntents-এ Read অনুমতি দিন।
5. টার্মিনালে নিচের কমান্ড চালান, নিজের কী বসিয়ে (চালানোর পর টার্মিনাল ইতিহাস মুছে ফেলা ভালো অভ্যাস):

```bash
curl https://api.stripe.com/v1/balance -u sk_test_XXXXXXXXXXXXXXXX:
```

6. Response-এ `"object": "balance"` আর `"livemode": false` খুঁজুন।
7. Dashboard → Developers → Logs-এ গিয়ে এই রিকোয়েস্টটি খুঁজে বের করুন।
8. ভুল কী দিয়ে (`sk_test_wrong`) আবার চালিয়ে কোন Status Code আসে দেখুন।

<details><summary>সমাধান দেখুন</summary>

- ধাপ ৬: `livemode: false` প্রমাণ করে আপনি টেস্ট পরিবেশে আছেন। Response-এ `available` আর `pending` নামে দুটি array থাকবে, টেস্টে সাধারণত অঙ্ক শূন্য বা খুব কম।
- ধাপ ৮: ভুল কী দিলে `401` আসবে, Body-তে `error.type` হিসেবে `invalid_request_error` এবং একটি মেসেজ যে কী সঠিক নয়। এটাই প্রত্যাশিত আচরণ।
- ধাপ ৪: Restricted Key দিয়ে অনুমতি নেই এমন কাজ (যেমন কাস্টমার তৈরি) করতে গেলে অনুমতি সংক্রান্ত এরর আসবে। এটা নিজে চালিয়ে দেখতে পারেন।

</details>

> [!MISTAKE]
> - Live Mode-এ আছেন খেয়াল না করে টেস্ট পেমেন্ট চালানো।
> - Secret Key স্ক্রিনশটে বা বাগ রিপোর্টে রেখে দেওয়া।
> - `.env` ফাইল `.gitignore`-এ না রেখে কমিট করা।
> - Publishable Key আর Secret Key গুলিয়ে ফেলা, ফলে ফ্রন্টএন্ডে Secret Key বসে যাওয়া।
> - কী ফাঁস হলে শুধু পোস্ট মুছে চুপ থাকা, Roll না করা।

## সারসংক্ষেপ

- Stripe অ্যাকাউন্ট ফ্রি; শেখার জন্য Test Mode বা Sandbox যথেষ্ট, Live লাগে না।
- Test Mode-এ আসল টাকা নড়ে না; Live Mode-এ সব আসল, তাই অনুমতি ছাড়া কখনো না।
- Dashboard-এর Payments, Customers, Developers (API keys, Webhooks, Logs, Events) QA-এর প্রধান জায়গা।
- Publishable Key ফ্রন্টএন্ডে চলে; Secret ও Restricted Key শুধু সার্ভারে।
- Secret Key কখনো GitHub, ফ্রন্টএন্ড, স্ক্রিনশট বা চ্যাটে নয়; ফাঁস হলে সাথে সাথে Roll।

## বাড়ির কাজ

1. Dashboard-এর Developers অংশের পাঁচটি সাব-পেজের নাম আর প্রতিটির একটি ব্যবহার লিখুন।
2. নিজের ল্যাপটপে একটি ফোল্ডারে `.env` আর `.gitignore` বানান, `.gitignore`-এ `.env` লিখুন। `git status` চালিয়ে নিশ্চিত হোন `.env` দেখাচ্ছে না।
3. পরের সপ্তাহে আমরা [Postman দিয়ে প্রথম API কল](/lessons/postman-first-api-call/) করব। তার আগে [টুলবক্স](/toolbox/) দেখে নিন।
