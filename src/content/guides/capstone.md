এই প্রজেক্টে আপনি পুরো কোর্সে যা শিখেছেন, সব একসাথে কাজে লাগাবেন। শেষে আপনার হাতে থাকবে একটি GitHub রিপোজিটরি, যেটা ইন্টারভিউতে সরাসরি দেখানো যায়।

সময়: ২ সপ্তাহ (প্রতিদিন ১–২ ঘণ্টা)। কোর্সের পুরো পথ দেখতে [রোডম্যাপ](/roadmap/) দেখুন।

## প্রজেক্টের পরিধি (Scope)

আপনি একটি ছোট ডেমো শপের Checkout টেস্ট করবেন। শপটি চলবে আপনার নিজের কম্পিউটারে, আপনার নিজের Stripe অ্যাকাউন্টের Test Mode (Sandbox)-এ।

### ডেমো অ্যাপ কোথা থেকে পাবেন

- **সহজ পথ:** Stripe-এর অফিসিয়াল নমুনা প্রজেক্ট [stripe-samples](https://github.com/stripe-samples) থেকে একটি Checkout নমুনা নিন (সেখানে “checkout” লিখে খুঁজুন)। README অনুযায়ী লোকালি চালান।
- **নিজে বানানো:** Node.js + Express দিয়ে ছোট একটি শপ: ৩টি পণ্য, কার্ট, Stripe Checkout Session তৈরি, আর একটি `/webhook` এন্ডপয়েন্ট যা অর্ডার “Paid” করে।

### যা টেস্ট করবেন

- কার্ট ও দাম: পরিমাণ, মোট দাম, কারেন্সি
- পেমেন্ট ফ্লো: সফল, decline, 3D Secure, বাতিল করে ফিরে আসা
- Stripe API: PaymentIntent/Checkout Session, Refund, Idempotency
- Webhook: `checkout.session.completed`, `payment_intent.payment_failed`, ডুপ্লিকেট ইভেন্ট
- নিজের অ্যাপের বেসিক সিকিউরিটি (নিচের সতর্কবার্তা দেখুন)

### যা পরিধির বাইরে

- Live Mode, আসল কার্ড, আসল গ্রাহকের ডেটা
- Stripe-এর নিজের সার্ভারে লোড টেস্ট বা সিকিউরিটি টেস্ট
- অন্য কারো ওয়েবসাইট

## ডেলিভারেবল চেকলিস্ট

> [!CHECK] জমা দেওয়ার আগে প্রতিটিতে টিক দিন
> সব ফাইল একটি পাবলিক GitHub রিপোজিটরিতে থাকবে, কোনো secret ছাড়া।

1. **টেস্ট প্ল্যান** (`docs/test-plan.md`): লক্ষ্য, পরিধি, পরিবেশ, ঝুঁকি, এন্ট্রি/এক্সিট ক্রাইটেরিয়া।
2. **কমপক্ষে ৪০টি টেস্ট কেস** (`docs/test-cases.csv` বা স্প্রেডশিট): positive, negative, edge case, webhook ও সিকিউরিটি মিলিয়ে।
3. **Postman collection ও environment** (`postman/`): environment-এ key-এর ঘর খালি বা `sk_test_XXXXXXXX` প্লেসহোল্ডার।
4. **Newman HTML রিপোর্ট** (`reports/`): htmlextra দিয়ে তৈরি।
5. **কমপক্ষে ৩টি Playwright টেস্ট** (`tests/`): অন্তত একটি UI আর একটি API টেস্ট।
6. **Webhook টেস্টের প্রমাণ**: Stripe CLI-এর `listen` ও `trigger` আউটপুটের স্ক্রিনশট বা লগ (secret ঢাকা)।
7. **৫টি বাগ রিপোর্ট** (`docs/bugs/`): সত্যিকারের পাওয়া বাগ, বা নিজে ইচ্ছা করে ঢোকানো বাগ (উল্লেখ করে দিন)।
8. **সিকিউরিটি চেকলিস্ট** (`docs/security-checklist.md`): শুধু নিজের অ্যাপের ওপর চালানো ফল।
9. **GitHub Actions রান**: প্রতিটি push-এ Newman ও Playwright চলে, সবুজ টিকের লিংক।
10. **README**: কী, কীভাবে চালাবেন, ফলাফলের সারাংশ, স্ক্রিনশট বর্ণনা।
11. **৫ মিনিটের ডেমো ভিডিও**: প্রজেক্টের মূল অংশ দেখিয়ে (YouTube unlisted বা Google Drive লিংক)।

## সিকিউরিটি অংশ

> [!DANGER] শুধু নিজের অ্যাপে
> সিকিউরিটি টেস্ট চালাবেন শুধু নিজের কম্পিউটারে চলা নিজের ডেমো শপে আর নিজের Stripe Test Mode-এ। অন্য কারো সাইট, কোনো আসল দোকান বা Stripe-এর সার্ভারে কোনো আক্রমণ, স্ক্যান বা লোড টেস্ট নয়। আসল কার্ড বা অন্যের তথ্য কখনো নয়। নিয়ম জানতে সাইটের নৈতিকতা নীতি ও [নৈতিকতা লেসন](/lessons/ethics-responsible-disclosure/) পড়ুন।

নিজের অ্যাপে যা যাচাই করবেন:

- ব্রাউজার থেকে দাম বা পরিমাণ বদলে পাঠালে সার্ভার নিজের হিসাবে চার্জ করে কি না ([পেমেন্ট লজিক লেসন](/lessons/payment-logic-vulnerabilities/))
- অন্য অর্ডারের ID দিয়ে অর্ডার দেখা যায় কি না
- Webhook-এ signature ছাড়া বা বদলানো বডি পাঠালে বাতিল হয় কি না ([Webhook সিকিউরিটি](/lessons/webhook-security/))
- একই ইভেন্ট দুইবার এলে অর্ডার দুইবার পূরণ হয় কি না
- Secret key ফ্রন্টএন্ডের কোডে, Git হিস্ট্রিতে বা লগে আছে কি না
- ত্রুটি বার্তায় ভেতরের তথ্য ফাঁস হয় কি না

## জমা দেওয়ার টিপস

> [!TIP] রিভিউয়ারের চোখে দেখুন
> একজন রিক্রুটার গড়ে কয়েক মিনিট দেখেন। README-এর শুরুতেই ফলাফলের সারাংশ, রিপোর্টের লিংক আর ভিডিওর লিংক দিন।

- কমিট করার আগে `git diff` দেখে নিশ্চিত হোন কোনো `sk_test_`, `whsec_` বা `.env` যাচ্ছে না।
- স্ক্রিনশটে key, ইমেইল বা ব্যক্তিগত তথ্য থাকলে ঝাপসা করুন।
- ইচ্ছা করে ঢোকানো বাগ হলে সেটা বাগ রিপোর্টে স্পষ্ট লিখুন। সততা ইন্টারভিউতে পয়েন্ট বাড়ায়।
- ছোট, অর্থপূর্ণ কমিট মেসেজ লিখুন।
- ভিডিওতে কোড না পড়ে কাজটা চালিয়ে দেখান: Newman রান, Webhook ইভেন্ট, একটি বাগ।
- পোর্টফোলিও সাজাতে [পোর্টফোলিও ও ইন্টারভিউ লেসন](/lessons/portfolio-interview-prep/) আর [ক্যারিয়ার গাইড](/career/) দেখুন।
