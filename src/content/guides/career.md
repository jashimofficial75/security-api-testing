পেমেন্ট টেস্টিং জানা QA-র চাহিদা বাড়ছে: ই-কমার্স, ফিনটেক, রাইড শেয়ারিং, কোর্স বিক্রির সাইট সবখানেই টাকার লেনদেন আছে। এই পাতায় কোন পথে এগোবেন, কী শিখবেন আর ইন্টারভিউতে কী জিজ্ঞাসা হয়, তা একসাথে দেওয়া হলো।

## ক্যারিয়ার পথ: ধাপে ধাপে

1. **Manual QA:** টেস্ট কেস লেখা, এক্সপ্লোরেটরি টেস্টিং, বাগ রিপোর্ট, বেসিক SQL, Jira বা এরকম টুল। HTTP ও JSON-এর ধারণা।
2. **API Tester:** Postman, collection ও environment, assertion, Newman, curl, Status Code ও JSON Schema বোঝা। API ডকুমেন্টেশন পড়তে পারা।
3. **Payment/Domain QA:** পেমেন্ট ফ্লো, Stripe Sandbox, টেস্ট কার্ড, Idempotency, Refund, Webhook, reconciliation। bKash, Nagad, SSLCommerz-এর মতো স্থানীয় গেটওয়ের ধারণা।
4. **SQA Automation Engineer:** JavaScript বা TypeScript, Playwright (UI + API), Git, GitHub Actions, রিপোর্টিং, স্থিতিশীল (flaky নয়) টেস্ট লেখা।
5. **SDET / Senior QA:** টেস্ট ফ্রেমওয়ার্ক ডিজাইন, contract testing, k6 দিয়ে পারফরম্যান্স টেস্ট, observability, কোড রিভিউ, টেস্ট স্ট্র্যাটেজি তৈরি।
6. **QA Lead / Security-minded QA:** টিম ও প্রসেস পরিচালনা, ঝুঁকিভিত্তিক পরিকল্পনা, OWASP Top 10 ও API Security, PCI DSS-এর মৌলিক ধারণা, নিরাপদ রিলিজ প্রক্রিয়া।

> [!TIP]
> সব ধাপ একসাথে নয়। একটা ধাপের কাজ দিয়ে পোর্টফোলিওতে প্রমাণ রাখুন, তারপর পরেরটায় যান। কোর্সের ক্রম দেখতে [রোডম্যাপ](/roadmap/) দেখুন।

## বাংলাদেশের চাকরির বাজার: টিপস

- **কোথায় খুঁজবেন:** bdjobs, LinkedIn Jobs, কোম্পানির নিজের ক্যারিয়ার পাতা, আর ফেসবুকের QA কমিউনিটি গ্রুপ। LinkedIn প্রোফাইলে “SQA”, “API Testing”, “Postman”, “Playwright” শব্দগুলো রাখুন।
- **সার্কুলারে প্রায়ই যা চাওয়া হয়:** ম্যানুয়াল টেস্টিং ও টেস্ট কেস, API টেস্টিং (Postman), বেসিক SQL, একটি অটোমেশন টুল (Playwright, Selenium বা Cypress), Git, Agile/Scrum-এর ধারণা, ভালো লিখিত ইংরেজি।
- **কারা পেমেন্ট জানা QA খোঁজে:** ফিনটেক, ই-কমার্স, সফটওয়্যার সার্ভিস কোম্পানি (যারা বিদেশি ক্লায়েন্টের Stripe-ভিত্তিক প্রোডাক্টে কাজ করে), রাইড ও ডেলিভারি অ্যাপ।
- **বেতন:** অভিজ্ঞতা, কোম্পানির ধরন (লোকাল বনাম বিদেশি ক্লায়েন্ট), শহর আর অটোমেশন দক্ষতার ওপর অনেক নির্ভর করে। সাধারণভাবে ম্যানুয়াল থেকে অটোমেশন ও SDET-এ গেলে বেতনের পরিসর উল্লেখযোগ্যভাবে বাড়ে। হালনাগাদ ধারণার জন্য সার্কুলার ও পরিচিত সিনিয়রদের সাথে কথা বলুন।
- **রিমোট কাজ:** বিদেশি রিমোট চাকরিতে ইংরেজিতে যোগাযোগ, পরিষ্কার পোর্টফোলিও আর GitHub-এ কাজের প্রমাণ বেশি গুরুত্বপূর্ণ।

## ইন্টারভিউ প্রশ্ন ও উত্তর

আরও প্রস্তুতির জন্য [পোর্টফোলিও ও ইন্টারভিউ লেসন](/lessons/portfolio-interview-prep/) দেখুন।

### পেমেন্ট

**১. Authorization আর Capture-এর পার্থক্য কী?**

<details><summary>উত্তর দেখুন</summary>

Authorization মানে কার্ডের টাকা আটকে রাখা (hold), Capture মানে আসলে টাকা কাটা। হোটেল বা রাইড অ্যাপে আগে authorize করে পরে আসল অঙ্ক capture করা হয়। Stripe-এ manual capture হলে PaymentIntent `requires_capture` স্ট্যাটাসে থাকে।

</details>

**২. একটি Checkout-এর জন্য কোন কোন negative টেস্ট করবেন?**

<details><summary>উত্তর দেখুন</summary>

Decline কার্ড, insufficient funds, expired card, ভুল CVC, 3D Secure ব্যর্থ বা বাতিল, নেটওয়ার্ক বিচ্ছিন্ন, পেমেন্ট পাতায় ফিরে আসা (back), ডাবল ক্লিক, শূন্য বা ঋণাত্মক পরিমাণ, আর মেয়াদোত্তীর্ণ সেশন।

</details>

**৩. পেমেন্ট সফল কিন্তু অর্ডার “Pending”: কী কী কারণ হতে পারে?**

<details><summary>উত্তর দেখুন</summary>

Webhook পৌঁছায়নি বা endpoint ত্রুটি দিয়েছে, signature যাচাই ব্যর্থ, ভুল ইভেন্ট শোনা হচ্ছে, অথবা ডেটাবেস আপডেটে বাগ। Stripe Dashboard-এর ইভেন্ট ও webhook delivery লগ আর সার্ভার লগ মিলিয়ে দেখব।

</details>

**৪. Refund টেস্টে কী কী যাচাই করবেন?**

<details><summary>উত্তর দেখুন</summary>

পূর্ণ ও আংশিক রিফান্ড, মূল অঙ্কের বেশি রিফান্ড আটকানো, একই রিফান্ড দুইবার না হওয়া, অর্ডারের স্ট্যাটাস আপডেট, `charge.refunded` ইভেন্ট, গ্রাহককে নোটিফিকেশন, আর শুধু অনুমতিপ্রাপ্ত ভূমিকা রিফান্ড করতে পারে কি না।

</details>

**৫. Reconciliation কী, QA কেন এটা নিয়ে ভাবে?**

<details><summary>উত্তর দেখুন</summary>

নিজের ডেটাবেসের অর্ডার আর গেটওয়ের লেনদেন মিলিয়ে দেখা। গরমিল মানে হয় টাকা কেটেছে কিন্তু অর্ডার হয়নি, বা উল্টো। QA এর জন্য মিলিয়ে দেখার টেস্ট আর রিপোর্ট যাচাই করে ([Reconciliation লেসন](/lessons/reconciliation-testing/))।

</details>

### API

**৬. 401 আর 403-এর পার্থক্য কী?**

<details><summary>উত্তর দেখুন</summary>

401 মানে আপনি কে, তা প্রমাণ হয়নি (key নেই বা ভুল)। 403 মানে পরিচয় ঠিক, কিন্তু এই কাজের অনুমতি নেই।

</details>

**৭. PUT আর PATCH-এর পার্থক্য কী?**

<details><summary>উত্তর দেখুন</summary>

PUT সাধারণত পুরো রিসোর্স বদলে দেয়, PATCH শুধু দেওয়া ফিল্ডগুলো আপডেট করে। Stripe-এর API অবশ্য আপডেটের জন্য POST ব্যবহার করে।

</details>

**৮. Postman-এ এক রিকোয়েস্টের ফল পরের রিকোয়েস্টে কীভাবে ব্যবহার করবেন?**

<details><summary>উত্তর দেখুন</summary>

প্রথম রিকোয়েস্টের Tests স্ক্রিপ্টে `pm.response.json()` থেকে ID নিয়ে `pm.collectionVariables.set()` দিয়ে রাখি, পরের রিকোয়েস্টে `{{pi_id}}` হিসেবে ব্যবহার করি।

</details>

**৯. API টেস্টে শুধু Status Code দেখা কেন যথেষ্ট নয়?**

<details><summary>উত্তর দেখুন</summary>

200 এলেও বডিতে ভুল অঙ্ক, ভুল কারেন্সি বা ফিল্ড বাদ থাকতে পারে। তাই বডির মান, schema, হেডার, রেসপন্স টাইম আর পার্শ্বপ্রতিক্রিয়া (ডেটাবেসে কী বদলাল) যাচাই করতে হয়।

</details>

**১০. Idempotency কী, পেমেন্টে কেন জরুরি?**

<details><summary>উত্তর দেখুন</summary>

একই রিকোয়েস্ট বারবার পাঠালেও ফল একবারই হবে। নেটওয়ার্ক timeout-এ ক্লায়েন্ট আবার চেষ্টা করলে যেন গ্রাহকের টাকা দুইবার না কাটে। Stripe-এ `Idempotency-Key` হেডার দিয়ে এটা করা হয়।

</details>

### Webhook

**১১. Webhook কী? Polling-এর সাথে পার্থক্য কী?**

<details><summary>উত্তর দেখুন</summary>

Webhook হলো ঘটনা ঘটলে সার্ভিস নিজে আপনার URL-এ খবর পাঠায়। Polling-এ আপনি বারবার জিজ্ঞাসা করেন “হয়েছে কি?”। Webhook দ্রুত ও কম অপচয়।

</details>

**১২. Webhook signature যাচাই কেন দরকার?**

<details><summary>উত্তর দেখুন</summary>

না করলে যে কেউ নকল “payment succeeded” ইভেন্ট পাঠিয়ে বিনা পয়সায় অর্ডার পূরণ করাতে পারে। Stripe `Stripe-Signature` হেডারে signing secret দিয়ে সই করে; সার্ভার raw body দিয়ে সেটা যাচাই করে।

</details>

**১৩. একই ইভেন্ট দুইবার এলে কী হওয়া উচিত?**

<details><summary>উত্তর দেখুন</summary>

দ্বিতীয়বার কিছু না বদলে 2xx ফেরত দেওয়া উচিত। ইভেন্ট ID সংরক্ষণ করে আগে প্রসেস হয়েছে কি না দেখা হয়। টেস্টে `stripe events resend` দিয়ে এটা যাচাই করি।

</details>

**১৪. Webhook ইভেন্ট ভুল ক্রমে এলে কী সমস্যা হয়?**

<details><summary>উত্তর দেখুন</summary>

Stripe ইভেন্টের ক্রম নিশ্চিত করে না। পুরোনো ইভেন্ট নতুন স্ট্যাটাসকে মুছে দিতে পারে। সমাধান: ইভেন্টের ওপর অন্ধভাবে নির্ভর না করে দরকার হলে API থেকে অবজেক্টের সর্বশেষ অবস্থা পড়া।

</details>

**১৫. লোকাল কম্পিউটারে Stripe Webhook কীভাবে টেস্ট করবেন?**

<details><summary>উত্তর দেখুন</summary>

`stripe listen --forward-to localhost:4242/webhook` চালিয়ে ইভেন্ট লোকালে আনি, আরেক টার্মিনালে `stripe trigger payment_intent.succeeded` দিয়ে ইভেন্ট বানাই, তারপর সার্ভার লগ ও ডেটাবেস যাচাই করি।

</details>

### সিকিউরিটি

**১৬. BOLA/IDOR কী? কীভাবে টেস্ট করবেন?**

<details><summary>উত্তর দেখুন</summary>

অন্য ইউজারের অবজেক্ট শুধু ID বদলে দেখা বা বদলানো যায়। নিজের অ্যাপে বা crAPI-এর মতো ল্যাবে দুইটি টেস্ট অ্যাকাউন্ট বানিয়ে একজনের টোকেন দিয়ে অন্যজনের অর্ডার ID চাই; 403 বা 404 আসা উচিত।

</details>

**১৭. ক্লায়েন্ট থেকে দাম পাঠানো কেন বিপজ্জনক?**

<details><summary>উত্তর দেখুন</summary>

ব্রাউজারের রিকোয়েস্ট বদলানো সহজ। সার্ভারকে পণ্যের ID নিয়ে নিজের ডেটাবেস থেকে দাম বের করতে হবে। ক্লায়েন্টের দামে চার্জ করলে কেউ ১০০০ টাকার পণ্য ১ টাকায় কিনতে পারে।

</details>

**১৮. PCI DSS কী? QA হিসেবে কী মাথায় রাখবেন?**

<details><summary>উত্তর দেখুন</summary>

কার্ড ডেটা নিরাপদে রাখার আন্তর্জাতিক মানদণ্ড। QA দেখবে কার্ডের পূর্ণ নম্বর বা CVC কোথাও লগ, ডেটাবেস বা স্ক্রিনশটে যায় না, আর কার্ড ফর্ম Stripe-এর হোস্ট করা উপাদান দিয়ে নেওয়া হয়।

</details>

**১৯. Card testing আক্রমণ কী? কীভাবে ঠেকানো হয়?**

<details><summary>উত্তর দেখুন</summary>

চুরি করা কার্ড বৈধ কি না দেখতে প্রতারকরা ছোট ছোট অনেক পেমেন্ট চেষ্টা করে। প্রতিরোধ: rate limit, CAPTCHA, Radar নিয়ম, ব্যর্থ চেষ্টার মনিটরিং। আমরা শুধু ধারণা ও প্রতিরোধ শিখি, আক্রমণ চালানো নয়।

</details>

**২০. অনুমতি ছাড়া কোনো সাইটে দুর্বলতা পেলে কী করবেন?**

<details><summary>উত্তর দেখুন</summary>

আর কিছু খোঁজাখুঁজি না করে, ডেটা না নিয়ে, কোম্পানির responsible disclosure বা bug bounty পাতা অনুযায়ী গোপনে জানাব। প্রকাশ্যে বলব না। শুরু থেকেই অনুমতি ছাড়া টেস্ট না করাই নিয়ম।

</details>

### অটোমেশন

**২১. কোন টেস্ট অটোমেট করবেন, কোনটা নয়?**

<details><summary>উত্তর দেখুন</summary>

বারবার চলে, স্থিতিশীল আর ঝুঁকিপূর্ণ ফ্লো (সফল Checkout, decline, রিফান্ড API) অটোমেট করি। একবারের, দ্রুত বদলায় এমন UI বা এক্সপ্লোরেটরি টেস্ট ম্যানুয়াল রাখি।

</details>

**২২. Flaky টেস্ট কী? কীভাবে কমাবেন?**

<details><summary>উত্তর দেখুন</summary>

কোড না বদলেও কখনো পাস, কখনো ফেল। কারণ: hard-coded wait, শেয়ার করা ডেটা, নেটওয়ার্ক। Playwright-এর auto-wait ও web-first assertion, আলাদা টেস্ট ডেটা আর স্থিতিশীল selector ব্যবহার করে কমাই।

</details>

**২৩. CI-তে Stripe key কোথায় রাখবেন?**

<details><summary>উত্তর দেখুন</summary>

GitHub Actions-এর Secrets-এ, শুধু Test Mode key, আর সম্ভব হলে সীমিত অনুমতির restricted key। কোডে, collection-এ বা লগে কখনো নয়।

</details>

**২৪. Playwright-এ UI টেস্টে Stripe Checkout-এর মতো তৃতীয় পক্ষের পাতা কীভাবে সামলাবেন?**

<details><summary>উত্তর দেখুন</summary>

Test Mode-এ টেস্ট কার্ড দিয়ে কয়েকটি মূল end-to-end টেস্ট রাখি। বেশিরভাগ যাচাই API লেভেলে ও নিজের অ্যাপের অংশে করি, কারণ বাইরের পাতার গঠন বদলাতে পারে।

</details>

**২৫. Newman রিপোর্ট টিমের কাছে কীভাবে কাজে লাগে?**

<details><summary>উত্তর দেখুন</summary>

প্রতিটি রানে কোন রিকোয়েস্ট ও assertion পাস/ফেল, রেসপন্স টাইম কত, তা HTML-এ দেখা যায়। CI-তে artifact হিসেবে রাখলে ডেভেলপার সরাসরি ব্যর্থতার কারণ দেখতে পারে।

</details>

## সাধারণ জিজ্ঞাসা (FAQ)

<details><summary>কোর্সটি কি সত্যিই ফ্রি?</summary>

হ্যাঁ, পুরোপুরি ফ্রি। কোনো রেজিস্ট্রেশন বা পেমেন্ট লাগে না। ব্যবহৃত টুলগুলোও ফ্রি বা ফ্রি প্ল্যানে চলে।

</details>

<details><summary>কোডিং না জানলে কি শুরু করতে পারব?</summary>

পারবেন। প্রথম কয়েক সপ্তাহ Postman ও ম্যানুয়াল টেস্টিং, কোডিং লাগে না। অটোমেশনের অংশে বেসিক JavaScript লাগবে, যা ধাপে ধাপে দেখানো হয়েছে।

</details>

<details><summary>Stripe Sandbox-এর জন্য কি আমার কার্ড লাগবে?</summary>

না। ইমেইল দিয়ে অ্যাকাউন্ট খুলে Test Mode (Sandbox) ব্যবহার করা যায়, ব্যবসা অ্যাক্টিভেট করতে হয় না। পেমেন্টে Stripe-এর টেস্ট কার্ড দেবেন; আসল কার্ড কখনো নয়।

</details>

<details><summary>বাংলাদেশ থেকে কি Stripe দিয়ে আসল ব্যবসা চালানো যায়?</summary>

Stripe কোন দেশে লাইভ ব্যবসা সমর্থন করে, তা Stripe-এর অফিসিয়াল তালিকায় দেখুন ([stripe.com/global](https://stripe.com/global))। এই লেখার সময় বাংলাদেশ সেই তালিকায় নেই। তবে শেখা ও টেস্টের জন্য Test Mode ব্যবহার করা যায়, আর অনেক বাংলাদেশি QA বিদেশি ক্লায়েন্টের Stripe-ভিত্তিক প্রোডাক্টে কাজ করেন। স্থানীয় গেটওয়ের জন্য [বাংলাদেশি গেটওয়ে লেসন](/lessons/bangladesh-gateways-sandbox/) দেখুন।

</details>

<details><summary>Windows ল্যাপটপে কি চলবে?</summary>

হ্যাঁ। Postman, Node.js, Stripe CLI, Playwright, VS Code সবই Windows-এ চলে। Docker Desktop-এর জন্য ভালো RAM (৮ GB বা বেশি) হলে সুবিধা।

</details>

<details><summary>সপ্তাহে কত ঘণ্টা দিতে হবে?</summary>

সপ্তাহে মোটামুটি ৮–১০ ঘণ্টা দিলে ৮–১০ সপ্তাহে কোর্স শেষ করা যায়। নিজের গতিতে চলুন; নিয়মিত অনুশীলন বেশি জরুরি।

</details>

<details><summary>কোর্স শেষে কি সার্টিফিকেট পাব?</summary>

না, কোনো অফিসিয়াল সার্টিফিকেট নেই। এর বদলে [ক্যাপস্টোন প্রজেক্ট](/capstone/) আর ল্যাবের কাজ দিয়ে GitHub পোর্টফোলিও বানান। নিয়োগকর্তারা সার্টিফিকেটের চেয়ে কাজের প্রমাণ বেশি দেখেন।

</details>

<details><summary>আমার অগ্রগতি কোথায় সংরক্ষণ হয়?</summary>

শুধু আপনার নিজের ব্রাউজারে। অন্য ডিভাইস বা ব্রাউজারে গেলে অগ্রগতি দেখাবে না, আর ব্রাউজারের ডেটা মুছলে তা মুছে যাবে।

</details>

<details><summary>সিকিউরিটি লেসন শিখে কি যেকোনো সাইটে টেস্ট করতে পারব?</summary>

না। শুধু নিজের অ্যাপ, নিজের Sandbox আর ইচ্ছাকৃতভাবে দুর্বল ল্যাব (Juice Shop, crAPI ইত্যাদি)। অনুমতি ছাড়া টেস্ট করা আইনত অপরাধ। বিস্তারিত: [নৈতিকতা লেসন](/lessons/ethics-responsible-disclosure/)।

</details>

<details><summary>প্রশ্ন বা ভুল পেলে কোথায় জানাব?</summary>

[যোগাযোগ পাতা](/contact/) থেকে জানান। প্রতিটি মতামত পড়া হয়।

</details>
